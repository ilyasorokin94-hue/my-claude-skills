# Модуль 08. Обход аудита: как сервер проходит все клиники по расписанию

Когда клиник несколько, аудит ставят на расписание ПК агентства: одна задача на
день, клиника выбирается сама. Chrome на ПК один, и задачи, которые пересекаются
по времени, пропускают запуск, поэтому по одной клинике за запуск и своё окно.

Сам аудит одной клиники — [модуль 01](01-audit-2-nedeli.md). Здесь только то, как
обход идёт без человека: выбор клиники, файл состояния, продолжение после сбоя,
сводка, сохранение работы. Образец — раздел «Обход всех клиник по расписанию»
[модуля 02](02-otzyvy-ezhednevno.md).

## Что лежит на ПК агентства

Список клиник аудита и рабочие файлы обхода живут в закрытой папке на ПК, в этот
репозиторий они не попадают:

```
<папка аудита>/
  spisok-klinik.md        код, путь к базе, неделя А или Б, день, статус
  zadaniya/               копии текстов задач расписания
  tmp/sostoyanie.json     состояние текущего запуска
  svodki/ГГГГ-ММ-ДД.md    отправленные сводки
  zhurnal-zapuskov.md     дата, клиника, версия скилла, минуты, блоки
  svodnaya/snimki-vse.csv строки snimki.csv всех клиник с кодом клиники
  vygruzki/<код>/         сырые выгрузки CRM и таблиц
```

ID организаций и счётчиков обход берёт **ссылкой** на список клиник обхода
отзывов, своей копии не держит: два списка разъезжаются. Буквы клиник для
обезличивания берутся из списка SEO-ведения, своя таблица соответствия не
заводится.

**Сырые выгрузки живут только в `vygruzki/`.** Ни в гит, ни в базы клиник, ни в
отчёты они не попадают. Срок хранения решает руководитель; пока решения нет,
предложение — 90 дней, дальше удаляем, агрегаты остаются в базе клиники.

## Ритм и выбор клиники

- Каждая клиника раз в 2 недели. Недели чередуются: А, Б, А, Б. У каждой клиники
  свой день, по три клиники в неделю.
- Какая клиника сегодня, считает [audit_sostoyanie.py](../scripts/audit_sostoyanie.py)
  по неделе и дню из списка клиник. Нет клиники на сегодня или клиника на паузе —
  **тихий выход** со строкой в журнале запусков, в чат ничего не уходит.
- Перенос аудита: не раньше чем на день и не позже чем на три, с записью в записке
  клиники, почему.

## Порядок запуска

1. **Сначала устройство, потом всё остальное.** Проверь, что выбран браузер этого
   ПК (отметка «на этом компьютере»), а не чужой из списка подключённых. Браузера
   этого ПК в списке нет — аудит не делаем: строка «нужен руководитель: Chrome не
   на связи» в сводку и отдельное сообщение в чат. Работать в чужом браузере нельзя
   даже на чтение.
2. **Клиника и её файлы.** Прочитай записку, профиль и `audit-nastroyki.md` прямо
   перед её очередью, а не заранее: так запреты и стиль одной клиники не
   смешиваются с другой.
3. **Аккаунт и организация.** Проверь, под каким аккаунтом Яндекса открыт Chrome и
   что открыта та самая организация по ID. Чужой аккаунт, выход из аккаунта, форма
   входа, код, капча — строка «нужен вход» в сводке и конец запуска. Входы делает
   только руководитель.
4. **Блоки аудита** по модулю 01. После каждого блока отметь его в
   `tmp/sostoyanie.json`: прерванный запуск продолжится с этого места, а не с начала.
5. **Отчёт, снимок, записка** в базу клиники. Строка снимка дублируется в
   `svodnaya/snimki-vse.csv` с кодом клиники.
6. **Сводка** в рабочий чат ([shablony/audit-svodka.md](../shablony/audit-svodka.md)).
7. **Сохранение работы** в GitHub: по базе клиники `git pull`, коммит
   «Аудит Карт ДД.ММ.ГГГГ», `git push` без force. Конфликт — остановись и напиши в
   сводку, руками ничего не разруливай. Пуш не прошёл — коммит всё равно делаем, а
   в сводку строка «работа не сохранена в GitHub: причина».

Только чтение и подготовка. Обход аудита ничего не публикует и не тратит денег:
даже очевидную правку он оформляет советом с готовой фразой «да, …» для
руководителя. Автоответы на отзывы — дело обхода отзывов (модуль 02), аудит в них
не лезет.

## Файл состояния

`tmp/sostoyanie.json`. Папка `tmp/` рабочая, в гит не попадает.

```json
{
  "data": "ГГГГ-ММ-ДД",
  "nedelya": "А",
  "den": "pn",
  "klinika": "<код базы>",
  "versiya_skilla": "4.0.0",
  "blokov_vsego": 16,
  "bloki_proydeny": [0, 1, 2, 3],
  "bloki_propushcheny": {"5": "подписки нет"},
  "prichina_ostanovki": "Яндекс Бизнес отдаёт 500 на статистике",
  "nachato": "ГГГГ-ММ-ДДTЧЧ:ММ",
  "proverok_sdelano": 0,
  "proverok_vsego": 2
}
```

- `bloki_proydeny` — номера блоков модуля 01, которые закончены.
- `bloki_propushcheny` — номер блока и причина: у каждого пропуска должна быть
  причина, иначе в отчёте он читается как «не проверяли».
- Запуск закончился нормально — файл удаляем.

## Если что-то пошло не так

| Что случилось | Что делаем |
|---|---|
| Chrome занят другой задачей | Ждём до 15 минут, потом строка «не начат: Chrome занят» в журнал запусков и тихий выход |
| Яндекс Бизнес лежит (500, 502, 503, 504, «что-то пошло не так», вкладка не грузится, таймаут) | Перезагрузи страницу один раз и подожди полминуты. Открылось — работаем дальше, поломки не было. Не открылось со второго раза — поломка: пишем файл состояния с пройденными блоками и ставим повторную проверку в свободное окно по правилу повторных проверок ПК агентства |
| Капча, выход из аккаунта, чужой аккаунт, нет браузера этого ПК | Это **не** поломка сервиса, время её не лечит: «нужен вход» в сводке, отдельное сообщение в чат, повторную проверку не ставим |
| Один блок не дался (нет доступа к счётчику, нет выгрузки заявок) | Блок в `bloki_propushcheny` с причиной, аудит идёт дальше. Пропуск попадает в отчёт и в журнал запусков |
| Аудит не уложился в окно | Доходим до конца текущего блока, пишем файл состояния, остаток добирает повторный запуск. В журнале запусков строка с минутами по блокам |

Сбой на одной клинике не переносится на другие: следующая клиника идёт в свой день.

## Сводка и журнал запусков

Сводка уходит каждый запуск, даже когда нового мало: по ней видно, что обход
отработал. Формат и что в неё нельзя — [shablony/audit-svodka.md](../shablony/audit-svodka.md).
Сводку всегда дублируй в сессии; не ушла в чат — так и напиши первой строкой.

В `zhurnal-zapuskov.md` одна строка на запуск: дата, клиника, версия скилла,
минуты, какие блоки пройдены, какие пропущены и почему. Это материал для
«Как улучшить скилл»: по нему видно, какие блоки всегда пустые и какие не
укладываются в окно.

## Задача расписания

Текст задачи: «Запусти `yandex-maps-analysis`, модуль 01: аудит Карт по
расписанию. Клинику выбери сама по неделе и дню. В конце отправь сводку в рабочий
чат». В заголовке задачи модель ставим аналитическую, не самую дешёвую: аудит —
это рассуждение, а не чек-лист.

Задачи создаёт руководитель или Claude по его «да». Копии текстов задач держим в
`zadaniya/` рядом со списком клиник: живые файлы задач лежат вне гита, и без копий
правила разъезжаются.

## Первый запуск

Первый запуск на новом ПК или с новой клиникой — тестовый
([rost-skilla.md](../rost-skilla.md)): одна клиника, только чтение, замер
длительности по блокам и сравнение с прошлым разбором этой клиники. По итогу
руководитель решает, ставить ли расписание.

## Что записать для скилла

Сколько минут занял аудит и каждый блок, на какой клинике и каком блоке
остановился и почему, какие блоки всегда пустые (кандидаты на слияние), сколько
раз сработала повторная проверка, какие пропуски повторяются от клиники к клинике.
