## 3.0.0 (21.11.2026, прямое решение руководителя, вступает в силу после слияния)

Ежедневная проверка отзывов стала обходом всех клиник со сводкой в рабочий
чат, а ответы на благодарности и нейтральные отзывы обход публикует сам.
Первая цифра, потому что меняются границы: раньше любой ответ публиковался
только по фразе руководителя.

- Границы, «Кто что решает»: исключение для автоответов на благодарности и
  нейтральные отзывы с замечанием. Негатив, «похоже на фейк», «не о нас» и
  всё спорное по-прежнему только по фразе руководителя.
- Границы, врачебная тайна: исключение по ответам для отдельной клиники со
  своим сложившимся стилем возможно только прямым решением руководителя,
  записанным в её профиле с датой.
- Модуль 02, «Обход всех клиник по расписанию»: одна задача на ПК агентства
  идёт по списку клиник, профиль читает перед очередью клиники, проверяет
  аккаунт Яндекса и организацию, пишет пакет в закрытую папку клиники, сбой
  на одной клинике не останавливает обход.
- Модуль 02, «Что обход публикует сам»: таблица по типам отзывов, шесть
  проверок перед публикацией, предохранители (не больше 10 ответов на клинику
  за запуск; отклонение модерацией или два провала проверки подряд
  останавливают автоответы по клинике).
- Модуль 02, «Что ждёт руководителя»: публикация по фразе для негатива и
  остального, что обход сам не публикует.
- Модуль 02, «Сводка обхода»: приходит каждый день, в том числе когда новых
  отзывов нет; нет сводки = обход не прошёл. В сводке только счётчики и
  статусы; срочное уходит отдельным сообщением сразу.
- Профиль клиники: раздел «Ответы на отзывы» с выключателем «Автоответы: да |
  нет», телефоном и почтой, своим стилем клиники.
- Новый скрипт `scripts/tg_report.py`: сводка в чат через бота Telegram,
  настройки только из переменных окружения `TG_BOT_TOKEN` и `TG_CHAT_ID`,
  режим `--proverka`, тесты в `scripts/tests/`.
- Новый шаблон `shablony/spisok-klinik.md`: список клиник обхода, хранится на
  ПК в закрытой папке.
- Не проверено тестовым прогоном: обход на ПК, автоответы и отправка в чат с
  настоящим ботом. Первый запуск по [rost-skilla.md](rost-skilla.md) идёт как
  тестовый: одна клиника, автоответы выключены, только чтение.

## 2.0.0 (20.11.2026, утверждено руководителем)

По разбору самого скилла: один непрерывный цикл, выводы отличают сигнал от
шума, база знаний стареет и сжимается, скилл растёт вместе с моделью. Первая
цифра, потому что меняется цикл (новые этапы), а не отдельный шаг.

- Непрерывность. Шаг 0: сверка версии с main перед каждым запуском (облачная
  среда может держать старую копию). Один цикл клиники: знакомство (00),
  накопление базы (новый модуль 05), ведение (01), пересмотр раз в квартал
  (новый модуль 06), поддержка (02–04). Записка следующему запуску
  (`shablony/zapiska.md`), снимок таблицей `snimki.csv`, расписание запусков
  как ориентир.
- Качество выводов. Коридор шума (компас 2, Z-11): за 2 недели визиты
  различают сдвиг около 20%, звонки около 80%, звонки и заявки судим за 4–8
  недель. Ожидаемый эффект правки записывается заранее; две правки в одну цифру
  = «не различить». Внешний контур: спрос, календарь, соседи как контрольная
  группа, сам Яндекс, год к году. Путь до визита и цена принятого звонка
  подписки раз в месяц, без выручки. Нейроответы раз в месяц, гипотеза H-06.
- Рост с моделью. `glavnoe-seychas.md`: 10–15 строк главного. У записей базы
  сила доказательства и дата проверки, старше 6 месяцев = «перепроверить».
  Свой взгляд до чтения базы. Журнал прогнозов (`shablony/prognozy.md`) со
  сверкой в разборе и итогом в пересмотре. Приёмы инструментов вынесены в
  `priemy.md` (M-07, M-08, M-09, M-11, M-12, Z-08, номера прежние).
- Одна система. Скилл главный по анализу, ритму, замерам и KPI Карт,
  материалы агентства отвечают «как оформить», расхождения идут одним уроком;
  одна очередь уроков на клинику. Раздел «Когда чего-то нет» (только облако,
  Базовый тариф, нет CRM, сеть филиалов). В каждом модуле «Как поймём, что
  сработало» и «Что записать для скилла». Цены клиник в базе обезличены (R-15,
  R-16), перед PR поиск по ценам, ID и телефонам.
- `card_weeks.py`: коридор шума по базовым неделям и итог двух последних,
  `--isklyuchit` для исключённых недель, неполная неделя не идёт в коридор,
  предупреждение при доле `drugoe` больше 5%, сводка в CSV.
- Модуль 01: разбор не ждёт обновления «Конкурентов», опора на счётчик.
