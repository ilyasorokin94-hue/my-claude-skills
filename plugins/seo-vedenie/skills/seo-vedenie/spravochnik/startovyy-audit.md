# Справочник. Стартовый аудит сайта клиники (блоки А–Е)

Перенесено из инструкции агентства «SEO-мониторинг» v1.1 (07.11.2026). Изменён только ритм: вместо «неделя, месяц, квартал» шаги идут каждый разбор (раз в 2 недели), через разбор и раз в квартал.

Делается один раз на знакомстве (модуль 00) и потом раз в год. Результат — список «что улучшить» в файле `otchety/ГГГГ-ММ-ДД-стартовая.md`, разложенный на четыре группы:

1. **Сделать сейчас** — техника, ссылки, разметка; тексты не меняются, решение руководителя не нужно (нужно только разрешение на загрузку).
2. **Нужно «да» руководителя** — меняются или добавляются тексты, цены, заголовки.
3. **Нужна клиника** — данные, согласия, доступы к карточкам.
4. **Потом** — новые страницы и статьи, когда квартальный аудит подтвердит спрос.

Проверяем шесть блоков. Если код сайта доступен (репозиторий или копия с хостинга), технику и ссылки Claude проверяет по коду целиком, иначе по живому сайту и отчётам кабинетов.

### А. Техника и индексация

- [ ] Одно главное зеркало: http, www и адреса с косой чертой и без неё ведут 301-редиректом на один вариант
- [ ] robots.txt не закрывает нужное; служебные разделы (спасибо-страница, формы, поиск, админка) закрыты; для Яндекса есть Clean-param для меток utm, yclid, gclid
- [ ] sitemap.xml содержит все живые страницы и только их, даты изменения настоящие; файл добавлен в оба кабинета
- [ ] У каждой страницы свои title, description, canonical и один H1; дублей нет
- [ ] Старые адреса после переезда или редизайна не отдают 404, а ведут 301 на ближайшую по смыслу страницу (список из Вебмастера, Search Console и логов сервера). Самая частая причина потери трафика у клиник после нового сайта
- [ ] Скорость на телефоне: Core Web Vitals в норме (шаг G9); нет заставок, тяжёлых видео и всплывающих окон на первом экране
- [ ] Все страницы по https, сертификат не истёк; сайт открывается и с мобильного интернета
- [ ] Нет тестовых копий сайта в открытом доступе (поддомены, превью) и служебных файлов в корне

### Б. Структура под спрос

- [ ] На каждую услугу со спросом в {регион Вордстата} есть своя страница (типовой набор для стоматологии — в шаблоне [karta-zaprosov.md](../shablony/karta-zaprosov.md))
- [ ] Есть страницы разделов (терапия, хирургия, имплантация, протезирование, ортодонтия, гигиена, эстетика, детская), и хлебные крошки ведут на них, а не на якоря или общий каталог
- [ ] Прайс ссылается из каждого раздела на страницу услуги; у каждой страницы услуги есть ссылки из текста других страниц, а не только из меню
- [ ] Статьи блога ссылаются на свою услугу, а услуга на статью по теме
- [ ] У каждого врача своя страница (фото, специальность, образование, стаж, услуги); страницы услуг ссылаются на своих врачей
- [ ] Есть страница контактов (или страница каждого филиала) с адресом, картой, часами и как добраться
- [ ] Нет двух страниц про одно и то же (статья и услуга под один запрос, две похожие услуги)

### В. Содержание страниц услуг

Каждую страницу услуги прогоняем по чек-листу сильной страницы услуги ([tipovye-problemy.md](tipovye-problemy.md)). В стоматологии чаще всего не хватает цен прямо на странице услуги: тогда запросы «{услуга} цена» уходят на общий прайс и стоят ниже, чем могли бы.

### Г. Местное SEO и карты

- [ ] Карточки в Яндекс Бизнесе, Google Business Profile и 2ГИС подтверждены, на каждый филиал своя
- [ ] Название, адрес, телефон, часы, e-mail и сайт совпадают слово в слово на сайте, в карточках и на медицинских площадках
- [ ] В карточке Яндекс Бизнеса сайт указан без UTM-меток: оттуда Вебмастер берёт регион сайта
- [ ] Кнопка записи в карточках ведёт на сайт или в систему записи клиники, а не теряет заявки в форме карт
- [ ] На отзывы в карточках отвечают; врачи есть на профильных площадках (ПроДокторов и другие)
- [ ] Фид «Врачи» в Вебмастере подключён или запланирован (шаг Я14)
- [ ] Разметка клиники (Schema.org Dentist или MedicalClinic) на главной или на контактах: адрес с индексом, телефон, часы, координаты, ссылки на карточки (sameAs)
- [ ] Нет страниц под соседние города и районы, где у клиники нет филиала: Google прямо называет такие страницы спамом (doorway)

### Д. Доверие и закон

Медицина для Google — тема YMYL, где доверие важнее всего. Те же сведения требует и закон, поэтому одна работа закрывает обе задачи. Юридическую полноту сверяет юрист клиники; аудит только отмечает, чего не видно.

- [ ] Юрлицо, ОГРН, ИНН, адрес и лицензия (номер, дата, кем выдана) доступны с каждой страницы; прайс, сведения о врачах, режим работы, образцы договоров и контролирующие органы размещены по Правилам платных медицинских услуг (ПП РФ № 736, действуют с 01.09.2023)
- [ ] На страницах услуг есть предупреждение о противопоказаниях; нет обещаний гарантированного результата, «случаев излечения» и благодарностей пациентов в виде цитат (риск по ФЗ «О рекламе», ст. 5 и 24); отзывы показываем ссылками и оценками площадок
- [ ] Фото клиники и врачей настоящие; стоковые или сгенерированные картинки только для иллюстраций лечения
- [ ] У статей указан автор или проверивший врач и дата (если клиника не решила иначе)
- [ ] Формы собирают согласие на обработку персональных данных, есть политика конфиденциальности и плашка cookie

### Е. Аналитика и заявки

- [ ] Сайт подтверждён в обоих кабинетах, доступ есть у руководителя и у клиники
- [ ] В Метрике настроены цели: заявка, звонок (нажатие на телефон), мессенджер, открытие записи
- [ ] Известно, как отличить заявку из поиска: источник в самой заявке, коллтрекинг или хотя бы логи сервера. Если на сайте плашка cookie, Метрика видит только согласившихся, и её цифры занижены
- [ ] Формы проверены тестовой заявкой с пометкой «ТЕСТ, не звонить» (с согласия руководителя)
