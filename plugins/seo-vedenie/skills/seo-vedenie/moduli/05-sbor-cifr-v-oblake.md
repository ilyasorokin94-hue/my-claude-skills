# Модуль 05. Сбор цифр в облаке

По желанию, дополнение к разбору. **Разбор его не ждёт**: всё, что нужно для
аудита, он читает в Chrome в том же запуске (компас 2, «Полный проход»;
решение руководителя от 22.11.2026). Сбор по API нужен для того, чего нет в
интерфейсе: выгрузки при застывшей статистике запросов, длинная история,
скорость через PageSpeed, регулярные снимки без человека. Токены живут в
облачной среде агентства, поэтому сбор идёт там и кладёт выгрузки в базу
клиники.

Это сбор, а не анализ: облачная сессия ничего не объясняет и ничего не решает.

## Как это связано с разбором

```
утро дня разбора: облачная сессия в среде агентства, репозиторий базы клиники
   │  API-скиллы ─► выгрузки и манифест в seo/dannye/ГГГГ-ММ/sbor-ДД/ ─► коммит в базу
   ▼
разбор на компьютере агентства: обновить базу ─► прочитать манифест
   │  свежий сбор есть ─► цифры из него; Chrome только для шагов вне API
   │  сбора нет или он неполный ─► недостающее снять в Chrome
   ▼
сверка, анализ, отчёт, ТЗ (модули 01–04)
```

Запускается по расписанию облачной среды в день разбора клиники (до времени
разбора) или строкой в облачном треде проекта клиники:

```
SEO-сбор цифр для [клиника] по скиллу seo-vedenie, модуль 05. Только чтение.
```

Расписание заводит руководитель или Claude по его «да».

## Что нужно один раз

- Сайт клиники и её счётчик доступны аккаунту агентства в Вебмастере и
  Метрике; сервисный аккаунт агентства добавлен в Search Console.
- Облачная сессия открывается на репозитории базы клиники и может в него
  писать. Скиллы в среду ставит её скрипт установки из main этого репозитория.
- В базе клиники есть `seo/profil.md`: домен, номер счётчика, регулярное
  выражение бренда, регион.

## Что снимает сбор

Период: последние 28 полных дней без последних 2–3 и предыдущие 28 (компас 2).
Параметры каждого скрипта смотри в `SKILL.md` его скилла, здесь только состав.

| Что | Чем | Когда |
|---|---|---|
| Сводка, диагностика, нарушения | yandex-webmaster: `summary.sh`, `host_info.sh`, `diagnostics.sh` | каждый сбор |
| Страницы в поиске, выпавшие и добавленные, важные страницы | `insearch.sh`, `search_events.sh`, `important_urls.sh` | каждый сбор |
| Запросы за период и за прошлый, история | `popular_queries.sh`, `queries_history.sh` | каждый сбор |
| Запросы и страницы с позициями | `query_analytics.sh` по запросам и по URL | каждый сбор |
| ИКС | `sqi_history.sh` | каждый сбор |
| Sitemap, история обхода, ссылки, фиды | `sitemaps.sh`, `indexing.sh`, `external_links.sh`, `internal_links.sh`, `feeds.sh` | через сбор (раз в месяц) |
| Google: клики, показы, позиции, бренд отдельно, сравнение периодов | google-search-console: `gsc.py perf --compare --brand`, `perf --dims page`, `quickwins` | каждый сбор |
| Google: индексация страниц из sitemap, sitemap | `gsc.py inspect --sitemap`, `gsc.py sitemaps` | каждый сбор |
| Скорость главной и 2–3 страниц услуг | `gsc.py psi`, `gsc.py crux` | через сбор |
| Переходы из поиска и заявки по источникам | yandex-metrika: `search_engines.sh`, `conversions.sh`, `goals.sh` | каждый сбор |
| Спрос по услугам и сезонность | yandex-wordstat | знакомство, пересмотр и когда записка просит |
| Выдача по главным запросам | yandex-search-api | только если в записке есть «да» руководителя с числом запросов |

Что именно просит ближайший разбор сверх обычного (запросы для замеров
созревших правок, спрос по новой группе), написано в `seo/zapiska.md`: сбор
читает её первой.

## Куда и как класть

Папка `seo/dannye/ГГГГ-ММ/sbor-ДД/` в базе клиники: файлы выгрузок как их
отдают скрипты (TSV, CSV) и манифест `sbor.md`:

```
# SEO-сбор цифр, [клиника], ГГГГ-ММ-ДД
Версия скилла: X.Y.Z. Среда: … . Период: ДД.ММ–ДД.ММ против ДД.ММ–ДД.ММ.

## Тревоги
Нарушения, фатальные ошибки диагностики, недоступность, обрыв данных. Или «нет».

## Что снято
| Файл | Что это | Чем снято |
|---|---|---|

## Что не удалось
| Что | Почему (ошибка, нет доступа, данные застыли с даты) |
|---|---|

## Осталось для браузера
Шаги, которых нет в API: переобход, запрос индексации, Алиса, уведомления.
```

Коммит в базу по её правилам (README базы). Сбор не трогает профиль, журнал,
записку и отчёты: только папку `dannye/`.

## Чего не делать

- Не анализировать и не выбирать правки: это делает разбор.
- Не отправлять переобход и не менять ничего в кабинетах.
- Не запускать платную выдачу без «да» в записке.
- Не выводить токены и ключи в файлы и в текст сессии.
- Не переписывать прошлые сборы: каждый сбор в своей папке.

## Когда сбора нет

Облачная среда недоступна, расписание не сработало, токен истёк: разбор идёт
через Chrome по [компасу 2](../kompas/02-istochniki-i-zamery.md) и пишет в
отчёте, чего из-за этого не хватило. Если сбор не приходит два разбора
подряд, это строка руководителю, а не привычка.

## Что записать для скилла

Какие выгрузки разбор ни разу не открыл (лишние), каких цифр ему не хватило и
пришлось добирать в браузере, ошибки скриптов и лимиты.
